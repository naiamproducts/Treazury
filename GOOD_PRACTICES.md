# Good Practices

Mandatory reading before working in this repo (see `AGENTS.md`). Process and
practices only — product and domain rules live in `AGENTS.md`.

## Language

- All repo text is English: docs, comments, identifiers, commit/PR messages, and
  UI copy.
- User-facing strings are never hardcoded: they live in the i18n catalog
  (`src/i18n/en.ts` + `t()`). Future locales are added to the catalog, never
  scattered through the code.
- Exception (legal output, not UI): the fiscal print HTML generated by
  `src/modules/invoicing/engines/venezuela.ts` stays Spanish.
- Spanish proper nouns and legal terms (RIF, SENIAT, IGTF) stay Spanish when
  technically required — as catalog values in `src/i18n/en.ts`, never hardcoded
  in component/UI code (the exception never licenses a literal "RIF" label in a
  component).

## Commits

- Work-unit commits: one deliverable per commit. Tests and docs ride with the
  change they belong to; the repo must make sense at every commit.
- Conventional Commits messages state the outcome, not a file list.
- Keep each PR under ~400 changed lines (count added lines; pure-doc
  rewrites and deletions are exempt); above that, split into chained slices.

## Verification before closing a task

- `bun run check` must be green. Note: it runs oxlint with `--fix`, so it can
  rewrite files — review the diff it produces.
- Reliable offline check: `bun scripts/test-commercial-docs.ts` (28 checks, no network, no side effects).
  `bun scripts/test-modules.ts` needs Arc RPC reachability or a cleared `VITE_ROUTER_OWNER_KEY`, may
  broadcast a testnet `createOrder`, and its summary/exit code can be stale — do not trust its exit code.
- Run the affected e2e specs: `bunx playwright test e2e/`. Prerequisites:
  `VITE_SUPABASE_URL` + `VITE_SUPABASE_PUBLISHABLE_KEY` set, `bunx playwright
  install` (chromium), and a seeded live account (helpers hardcode a sandbox
  account). Missing env fails as login-locator timeouts (hangs), not env
  errors; when offline fall back to `bun run check` + `bun scripts/test-commercial-docs.ts`.
- Docs-only changes state an explicit `N/A` instead of a test run.

## Docs hygiene

- No stale docs: delete an obsolete doc in the same change that obsoletes it.
- `openspec/` is the source of truth for product decisions.
- Never restate facts that live in code (addresses, fees) without citing where
  they were verified.

## Generated files

- Never hand-edit `src/onchain-facts.ts` or `src/onchain-money.ts` — both are
  generated by Arc Studio.
